# Architecture and shared conventions

All sub-agents follow this file. The project root is
`geometry-dash` (called ROOT below).

## Hard rules
- Stay inside ROOT. Never touch sibling folders.
- Never run git commands of any kind.
- Never tick a TESTS.md item without real command output. Things only a human can check are
  marked `MANUAL — pending user`.
- Do not leave windows or processes running. Headless runs use
  `SDL_VIDEO_DRIVER=dummy SDL_AUDIO_DRIVER=dummy`.
- C++20, Apple clang, CMake + Ninja. Warnings on (`-Wall -Wextra`), no warnings in our code.
- Code must stay portable (Linux/Windows): no Apple-only APIs in our code.

## Layout
```
CMakeLists.txt            top-level; FetchContent deps (URL tarballs, pinned release tags)
src/core/                 gd_core static lib. PURE logic. NO SDL includes. Uses nlohmann/json.
  PhysicsConstants.h      THE single source of physics constants (game, tests, tools share it)
  Level.h / Level.cpp     level data model + object palette (owned by level-format section)
  LevelLoader.h/.cpp      JSON -> Level (level-format section)
  Validator.h/.cpp        palette + completability checks (level-format section)
  Aabb.h                  AABB math (scaffold)
  FixedTimestep.h         accumulator for fixed-step loop (scaffold)
  StateMachine.h          app state enum + transition table (scaffold; menus extend)
  Sim.h / Sim.cpp         deterministic gameplay simulation (physics section)
  Replay.h / Replay.cpp   input replay file format + runner (physics section)
  Solver.h / Solver.cpp   automatic input search that beats a level (solver section)
  Progress.h/.cpp         attempts / best % persistence, path injected (menus section)
src/app/                  SDL3 front end (renderer, audio, menus, main.cpp). Only place SDL is used.
tools/                    CLI tools linking gd_core: gd_validate, gd_replay, gd_solve
tests/                    doctest suites, one file per module: test_<module>.cpp, single runner gd_tests
levels/level01.json ..    the 10 levels
replays/level01.replay .. passing input replays (generated by gd_solve, checked by gd_replay)
assets/{music,sfx,fonts,sprites}/   media; every file logged in LICENSES.md
docs/LEVEL-FORMAT.md      authoritative object palette + JSON format
TESTS.md                  test script / checklist (each section appends its part)
LICENSES.md               every third-party asset and library
handoff.md                final state + resume doc (lead writes)
```

## Build targets
- `gd_core` (static lib), `geometry_dash` (game exe), `gd_tests` (doctest runner),
  `gd_validate`, `gd_replay`, `gd_solve`.
- Build dir: `ROOT/build`. Commands:
  - `cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release`
  - `cmake --build build`
  - `ctest --test-dir build --output-on-failure`
- ctest registers: `unit` (gd_tests), `validate_levelNN` (gd_validate per level),
  `replay_levelNN` (gd_replay per level), `smoke` (headless game run). Register a level/replay
  test only if its file exists (glob at configure time).
- Data dir: game and tools find `levels/` and `assets/` via `--data <dir>`, else the compile
  definition `GD_DATA_DIR` (= ROOT). No copying of assets into build/.

## Coordinates and units
- 1 world unit = 1 block. x grows right, y grows up. Ground surface is y = 0 (solid below).
- World ceiling at y = `level.ceiling` (default `kDefaultCeiling`), solid.
- Object `x`,`y` are the bottom-left corner of the object, in blocks.
- Player is a `kPlayerSize` square. Player x position = left edge. Player starts at x = 0, on the
  ground (cube) or at y = 1 (ship). Horizontal speed is constant per speed setting.
- Simulation runs at a fixed `kTickRate` (240 Hz). One `Sim::step(bool held)` = one tick.
  The app renders at display rate and interpolates; the sim never sees wall-clock time.
- Use `double` in the sim. No `rand()`, no time-based logic: identical inputs → identical states.

## Naming
- Namespace `gd`. Physics constants in `gd::phys`. Files PascalCase, functions camelCase,
  constants `kName`, types PascalCase.
- Headers use `#pragma once`.

## CLI flags for `geometry_dash`
- `--data <dir>` data root.
- `--level N` start level N directly (1..10).
- `--practice` start in practice mode.
- `--fly` debug fly mode: player cannot die (for sanity-checking levels).
- `--replay <file>` drive input from a replay file.
- `--smoke <frames>` run N frames then exit 0 (fails non-zero on any error).
- `--screenshot <out.bmp> --frame <K>` render frame K to a BMP then exit (convert with
  `sips -s format png in.bmp --out out.png` and inspect).
- `--frame-every K --screenshot-dir DIR` save a BMP every K frames. Stops at the shot cap or when the level completes.
- `--max-shots N` shot cap for `--frame-every` (default 20, max 200). Prints one stderr warning when the cap is hit.
- `--hitboxes` outline hitboxes: player outer (green) and inner (red), spikes (magenta), blocks and platforms (yellow).
- `--mute` no audio.
- `--save <path>` progress file; `--menu-script "down,enter,..."` scripted keys (headless tests).
